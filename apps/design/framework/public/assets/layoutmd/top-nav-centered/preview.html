Designing for dark mode without doubling your work

EN
Emma Nguyen
Principal Designer
Jul 8, 2026 · 9 min read

Dark mode is no longer a nice-to-have. Yet too many teams treat it as a second design pass — a costly mistake that a token-first approach quietly eliminates.

When we first shipped a dark theme, we did it the hard way: a parallel set of screens, hand-tuned for every surface. It looked great on launch day and became a maintenance nightmare within a month. Every new component meant designing it twice, and the two themes drifted apart with every release.

Start with semantic tokens

The breakthrough came when we stopped thinking in raw colors and started thinking in roles. Instead of gray-100, we defined surface. Instead of gray-900, we defined text. Each role resolves to a different value per theme, but every component references the role, never the raw value.

Design the meaning once, and let the theme decide the pixels.

This inversion is deceptively powerful. A new card component automatically works in both themes because it consumes surface, border and text — roles that already know how to behave everywhere.

Mind contrast, not just color

Dark mode is where contrast bugs hide. A border that reads perfectly on white can vanish on a near-black surface. We built a contrast check into the token pipeline so any pair falling below the threshold fails the build before it ever reaches a screen.

The same discipline applies to data visualisation. Grid lines follow the border token, series colors keep their brand hue but lower their fill opacity, and everything stays legible regardless of the active theme.

Ship it as a switch, not a rewrite

Because the whole system pivots on a single data-theme attribute, toggling themes is a one-line change at runtime. There is no duplicated markup, no conditional components, and — crucially — no second design surface to keep in sync.

Six months on, adding dark support to a new feature costs us nothing extra. That is the real payoff: not the dark theme itself, but a system where the theme is simply a property of the design, not a project of its own.
