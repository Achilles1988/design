# Product

## Register

product

## Users

Developers and design engineers working inside a local repository. They use the
tool during implementation to create, inspect, refine, and share real
front-end design drafts without leaving the engineering workflow.

## Product Purpose

Design Engineering provides a fast, trustworthy design step for software
projects. It manages Apps, blank Canvases, reusable design assets, and
AI-assisted authoring on disk. Success means users can move from an empty
Canvas to a reviewable, compilable interface quickly, while preserving the
App's Style, Layout contracts, reusable components, and repository boundaries.

## Brand Personality

Restrained, professional, efficient. The product should feel precise and calm,
with the confidence of a focused engineering tool.

## Anti-references

- Playful consumer-product styling that distracts from the work.
- Decorative excess, glass effects, oversized rounding, or ornamental motion.
- Generic AI or SaaS card grids, gradient-heavy surfaces, and dashboard filler.
- Visual novelty that obscures state, permissions, errors, or the next action.

## Design Principles

- Keep the work primary: the Shell supports the Canvas and never competes with it.
- Make system state explicit: readiness, permissions, pending work, failures,
  and recovery paths must be easy to understand.
- Practice the contracts: reuse installed Style, Layout, and component systems
  instead of inventing parallel UI conventions.
- Favor confident restraint: use hierarchy, spacing, and precise language
  before decoration.
- Preserve user control: AI proposes, explains, and waits for confirmation
  before changing files or configuration.

## Accessibility & Inclusion

Target WCAG 2.1 AA. All primary workflows must support keyboard navigation,
visible focus, readable contrast, semantic status communication, and reduced
motion preferences. Color must not be the only carrier of meaning.
